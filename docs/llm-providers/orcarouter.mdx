[OrcaRouter](https://www.orcarouter.ai) is an OpenAI-compatible gateway to models from OpenAI, Anthropic, Google, DeepSeek, and others through a single API key. Its [Cyber Inference tier](https://www.orcarouter.ai/cyber) is built for authorized security work: models a security team can switch on for scoped, authorized engagements, so an agent like Strix isn't stopped by a general-purpose model's blanket refusals in the middle of a sanctioned test.

## Setup

Use the `orcarouter/<model id>` format and pick one of two ways to authenticate.

### API key

```bash
export STRIX_LLM="orcarouter/orcarouter/auto"
export ORCAROUTER_API_KEY="sk-orca-..."
```

`LLM_API_KEY` works too, like every other provider.

### Sign in with your OrcaRouter account

No key to copy: Strix opens the OrcaRouter consent screen in your browser (OAuth 2.0 with PKCE) and stores the API key it issues in `~/.strix/subscription-auth.json`.

```bash
strix auth login orcarouter              # approve in the browser
export STRIX_LLM="orcarouter/orcarouter/auto"
strix auth status orcarouter             # show which credential is in use
```

On a machine where the browser can't reach back to the terminal (SSH, containers), add `--manual`: OrcaRouter shows a code on the consent screen and you paste it into the terminal.

The issued key has no expiry and is reused on every run until you revoke it at [Authorized apps](https://www.orcarouter.ai/console/authorized-apps). If OrcaRouter rejects it, Strix asks you to run `strix auth login orcarouter` again. `strix auth logout orcarouter` removes the stored key from this machine.

When more than one credential is present, Strix uses `ORCAROUTER_API_KEY` first, then the signed-in key, then `LLM_API_KEY`.

## Models for security testing

Every id uses the `orcarouter/<model id>` form. Browse the full [Cyber Inference catalog](https://www.orcarouter.ai/models?tier=cyber):

| Tier | Model | `STRIX_LLM` |
|------|-------|-------------|
| Default — works with any key | Adaptive routing | `orcarouter/orcarouter/auto` |
| Dedicated cyber | OrcaCyber Ultra | `orcarouter/orcacyber-ultra-1.0` |
| Dedicated cyber | OrcaCyber Zero | `orcarouter/orcacyber-zero-1.5` |
| General fallback | OrcaRouter Fusion | `orcarouter/orcarouter/fusion` |

- **`orcarouter/auto`** is the zero-config default: it routes each request to a capable upstream model and works with any OrcaRouter key.
- **OrcaCyber Ultra** and **OrcaCyber Zero** are the dedicated [Cyber Inference](https://www.orcarouter.ai/cyber) models, tuned for authorized red-team and blue-team workflows. A security team unlocks them once OrcaRouter has verified the engagement is scoped and authorized.
- **`orcarouter/fusion`** is a general-purpose fallback for when a cyber-tier model isn't enabled.

For agentic scans, pin a model with tool-calling support. Any chat model in the [OrcaRouter catalog](https://api.orcarouter.ai/v1/models) also works as `orcarouter/<model id>`.

## Get API Key

1. Go to [orcarouter.ai](https://www.orcarouter.ai)
2. Sign in and open the console
3. Create a new API key

## Self-hosted gateways

`ORCA_BASE_URL` points both sign-in and inference at one origin. `ORCA_AUTH_BASE_URL` and `ORCA_API_BASE_URL` (including `/v1`) override each side separately and take precedence. Remote origins must use `https://`.
